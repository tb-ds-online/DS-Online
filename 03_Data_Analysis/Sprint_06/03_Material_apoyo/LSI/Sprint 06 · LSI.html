SELECT g.Name AS genero, SUM(i.Total) AS ventas
FROM invoices AS i
JOIN invoice_items AS ii ON i.InvoiceId = ii.InvoiceId
JOIN tracks AS t ON ii.TrackId = t.TrackId
JOIN genres AS g ON t.GenreId = g.GenreId
GROUP BY g.Name
ORDER BY ventas DESC

Vídeo · SQL con Python: ordenación, agregación y agrupación

  
El orden de las cláusulas siempre es el mismo

  

    


SELECT   id_departamento, COUNT(*) AS n  -- 5
FROM     Empleados                       -- 1
WHERE    id_departamento IS NOT NULL     -- 2
GROUP BY id_departamento                 -- 3
HAVING   n > 1                           -- 4
ORDER BY n DESC                          -- 6
LIMIT    10                              -- 7


   id_departamento  n
0               10  2

    

    

      

        
SQLpandas

        
COUNT(*) · COUNT(col)size() · count()

        
SUM · AVG · MIN · MAXsum · mean · min · max

        
DISTINCTdrop_duplicates() · unique()

        
ORDER BY ... DESCsort_values(ascending=False)

        
LIMIT 10head(10)

      

      
WHERE o HAVINGWHERE filtra filas antes de agrupar; HAVING filtra grupos después. Los números marcan en qué orden lo procesa la base de datos: tabla, filas, grupos, grupos que se quedan, columnas, orden y límite.

Vídeos · SQL en Python: gestión BD I y II

  
Escribir en la base de datos: siempre con ? y con commit

  


cur.execute('''
    CREATE TABLE IF NOT EXISTS alumnos (
        id     INTEGER PRIMARY KEY,
        nombre TEXT NOT NULL,
        nota   REAL)''')

alumnos = [("Luis", 8.5), ("O'Brien", 6.25)]
cur.executemany(
    "INSERT INTO alumnos (nombre, nota) VALUES (?, ?)",
    alumnos)

cur.execute("UPDATE alumnos SET nota = ? WHERE nombre = ?",
            (7, "Luis"))
cur.execute("DELETE FROM alumnos WHERE nota < ?", (5,))

con.commit()     # sin esto, los cambios no se guardan

    

      
Por qué ?Con un f-string, el apóstrofo de O'Brien rompe la consulta (OperationalError: near "Brien": syntax error). Y si el texto viene de un usuario, puede colar SQL dentro: es la inyección SQL.

      
Sin WHEREUPDATE y DELETE sin WHERE cambian o borran todas las filas.

      
commitHasta el commit, otra conexión no ve los cambios y se pierden si se cierra sin guardar.

    

  






  
Vídeos · REST APIs · Ejemplo AEMET

  
Una petición: dirección, parámetros y clave. Una respuesta: código y JSON

  

    


import os
import requests

base_url = "https://opendata.aemet.es/opendata"
endpoint = "/api/prediccion/especifica/playa/{playa}"

url = base_url + endpoint.format(playa=codigo)
api_key = os.environ["AEMET_API_KEY"]

r = requests.get(url, params={"api_key": api_key})

r.status_code      # 200 si ha ido bien
datos = r.json()   # dict o lista de Python

      
La clave, fuera del códigoGuardadla en una variable de entorno o en un .env que esté en .gitignore. Una API key subida a GitHub es pública.

    

    

      
CódigoSignifica

      
200Todo bien

      
400La petición está mal: falta o sobra un parámetro

      
401 · 403Sin clave, clave mala o sin permiso

      
404Esa dirección no existe

      
429Demasiadas peticiones: hay que esperar

      
500Fallo del servidor, no vuestro

    

  

  
params monta la URL por vosotros: {"q": "Las Arenas", "dias": 3} se convierte en ?q=Las+Arenas&dias=3.
