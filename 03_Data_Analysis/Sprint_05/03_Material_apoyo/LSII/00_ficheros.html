Para qué sirve

Pregunta

Si pandas lee CSV, ¿para qué más formatos?

1

Negocio os manda Excel

Y en España, con ; entre columnas y coma en los decimales. Si no lo sabéis leer, sale todo en una columna.

2

Las APIs hablan JSON

Una API o un LLM con respuesta estructurada devuelve JSON, a menudo anidado.

3

Los LLMs comen JSONL

Las Batch API y el fine-tuning de OpenAI piden un .jsonl: una petición o un ejemplo por línea.

4

Los datasets vienen en Parquet

Hugging Face publica cada vez más datasets en Parquet, y DuckDB los consulta sin descargarlos.

5

Los logs crecen rápido

Un chatbot genera millones de filas. En CSV pesan y tardan; en Parquet, mucho menos.

En resumen

Elegir mal el formato no da error: da tipos cambiados, ceros perdidos y ficheros que no caben.

8 columnas: id, fecha, modelo, categoría, tokens, latencia, acierto y valoración.

    

    

      
Por qué pesa menosParquet guarda los datos por columnas. Una columna con solo tres modelos distintos se comprime muchísimo.

      
Por qué se lee más rápidoSi solo necesitáis dos columnas, Parquet lee esas dos y salta el resto. Un CSV hay que recorrerlo entero.

      
Por qué JSONL pesa tantoRepite el nombre de cada columna en cada línea: un millón de veces "latencia_ms".

    

  






  
Para decidir

  
Cada formato tiene su sitio

  

    
FormatoLo buenoLo maloDónde lo veréis

    
CSVLo abre cualquiera, Excel incluido.No guarda tipos: ceros, fechas y decimales se pueden perder.Exportaciones de negocio, datasets pequeños.

    
ExcelEs lo que usa negocio.Varias hojas, celdas combinadas, fórmulas. Necesita openpyxl.Informes, presupuestos, listados a mano.

    
JSONAdmite datos anidados.Hay que aplanarlo para tener una tabla.APIs, configuración, respuestas de un LLM.

    
JSONLUn registro por línea: se puede añadir y leer por partes.Pesa mucho.Logs, datasets de texto, Batch API y fine-tuning.

    
ParquetGuarda tipos, comprime y lee solo las columnas que pedís.No se abre con un editor de texto. Necesita pyarrow.Datasets de Hugging Face, data lakes, datos intermedios de un proyecto.

  

  
Regla prácticaLeed lo que os manden en el formato que venga. Lo que guardéis vosotros para seguir trabajando, en Parquet.

Qué tenéis que dominar y qué no

  

    
Lo que vais a usar a diario
  • read_csv con sep, decimal, encoding, dtype y parse_dates
  • read_excel y sheet_name
  • read_json, lines=True y json_normalize
  • to_parquet y read_parquet, también con columns
  • merge para juntar tablas de sitios distintos
  • una consulta sencilla con duckdb.sql(...).df()

    
Para lo que no os va a servir
  • Sustituir una base de datos compartida: DuckDB es para trabajar en vuestro ordenador.
  • Abrir un Parquet con el bloc de notas: es binario.
  • Memorizar los parámetros de cada read_*: se consultan en la documentación.

  

  
La ideaLeer bien es decirle a pandas lo que no puede adivinar: el separador, los decimales, la codificación y los tipos. Guardar bien es usar un formato que no los olvide.
